# 节奏体检 · PaceCheck

**拖一个视频进去，它逐帧量这个片子到底在不在「动」，然后告诉你哪几段是幻灯片。**

纯前端，单个 HTML 文件。不用装东西、不用联网、文件不会上传到任何地方。双击 `index.html` 就能用。

![播放器里的报告：判定「像幻灯片」](docs/report-slideshow.png)

---

## 它解决什么问题

现在用 AI 做视频的人越来越多，做出来的东西也越来越像：画面漂亮，但整片是「翻页」。
一镜停六秒、元素入场之后就再也不动——观众说不清哪儿不对，就是划走了。

这件事肉眼很难判。你自己盯着看十遍也会觉得「它在动啊」。所以要量。

## 量什么

把每帧缩到 480px 宽、转灰度，取**相邻帧的平均绝对差**（0–255）。这个数就是「这一帧相比上一帧，有多少像素变了、变了多少」。

一条正常的片子，这个数在中位 2–5 之间；一个幻灯片，中位 0.1 上下。

| 项 | 阈值 |
| --- | --- |
| 低动帧 | 动能量 < 0.6 |
| 幻灯片 | 中位 < 1.2 **且** 低动帧 > 70% |
| 静止段 | 连续 1.2 秒以上低动 |
| 切点 | 跟前后 0.5 秒的局部中位数比，突增 3 倍以上 |
| 偏黑帧 | 亮度低于「全片中位亮度 × 0.35」 |

## 三条踩出来的经验

这三条是做完才发现、而且反直觉的，也是这个工具跟「凭感觉看片」的区别：

1. **小面积运动不算运动。** 13px 的跑马灯、1px 的细线、几颗飘动的粒子，占的像素比例太低，降采样之后贡献不到 0.1。要动就动大面积。
2. **随机颗粒不算运动。** 逐帧换位置的噪声，在 4×4 块平均之后互相抵消，量出来接近 0。颗粒是质感，不是运动。
3. **挪黑的地方不算运动。** 如果画布 96% 是近黑，把一块黑挪 30px，差值还是 0。这解释了为什么有些「加了 glitch 特效」的片子，测出来跟没加一样。

## 两处工程细节

- **采样必须按 30fps。** 采样率降到 15fps，帧差会被放大一倍，阈值就对不上了。
- **暗调片子要用相对判据。** 黑底风格的片子，底色本身亮度就接近 0；用绝对阈值会把正常帧误报成黑场。所以黑场线取 `min(40, 全片中位亮度 × 0.35)`，且当全片中位亮度本身 < 8 时不判黑场。

## 验证

拿两支已知结果的片子跑过，判定和人工结论一致：

| 片子 | 中位动能量 | 低动帧 | 最长静止 | 判定 |
| --- | --- | --- | --- | --- |
| 43.8s，重做前 | 0.083 | 84.8% | 9.0s | **像幻灯片** |
| 45s，重做后 | 3.481 | 2.1% | 0s | **正常** |

## 命令行版

`verify.mjs` 是同一套算法的命令行实现，走 ffmpeg 抽帧，用来批量跑和回归。只需要 Node 和 ffmpeg，没有第三方依赖。

```bash
node verify.mjs your-video.mp4
```

输出：

```json
{
 "frames": 1314,
 "seconds": 43.8,
 "median": 0.083,
 "lowRatio": 0.848,
 "longestFreeze": 9,
 "darkFrames": 5,
 "cuts": 2,
 "verdict": "像幻灯片"
}
```

## 它不能告诉你什么

- 不能告诉你片子好不好看。节奏对了不等于好看，只是不至于让人以为卡了。
- 不能判断内容。它只看像素变化。
- 对刻意设计的「静」（比如全片留一秒完全静止再接一个大冲击）会报 warn，那是故意的，忽略即可。
